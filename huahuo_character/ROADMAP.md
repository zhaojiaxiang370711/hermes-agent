# 角色 Agent 后续阶段

第一阶段已有角色配置、独立 session、受限接话、Hermes 本机 HTTP 适配和 Godot 动作桥接；验证范围见 [README](README.md)。继续沿独立扩展开发，升级上游时保留固定基线与契约检查，避免将角色业务改入 Hermes 核心循环。

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1：框架基础 | 角色身份、会话、接话预算、动作消息与可选消费端 | 离线协议、真实本机测试 HTTP 服务器、旧回合失效及现有动作优先级通过；本次完成 |
| 2：当前游戏与语音 | 接现有 Python ASR/TTS，建立长期运行场景服务；Hermes SSE 回复；Godot 绑定对应角色 | 派蒙真实文本/语音往返通过，插话立即生效；断连/切角色/重启无迟到动作；重复情绪通道合并；完成双摄大屏现场回归 |
| 3：独立关系与多角色 | 可信用户身份、角色与用户关系记忆分区、用户删除、状态清理、角色主动接话预算 | 不同用户无记忆串用；角色只获授权场景事实；恢复和多角色成本/延迟可追溯 |
| 4：动画动作驱动 | 能力协商、每角色 clip 映射、语音时间点、动作完成/取消/失败回执；表情与注视 | 实际资产动作与台词同步，过期/忙时语义明确；手部和拍照状态优先，失败可回退 |
| 5：地面与空间行为 | 可莉等地面角色目标、导航、避障及接触意图 | Agent 只发目标意图；Godot 执行路径、碰撞、IK和物理约束；固定房间真人验证通过 |

动画、逐帧骨骼、物理与导航保留在引擎内，不为每帧调用 LLM。未来开放工具以类型化、可撤销的角色能力为单位，先增加实际消费端和验收，再扩展抽象。

阶段 2 尚未完成，没有运行常驻 Hermes 服务、访问模型供应商或接入现有实景游戏。后续阶段是开发路线，不是已交付功能或自动定期任务。
